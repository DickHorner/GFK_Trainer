# Copilot Development Instructions for GFK-Trainer

## Project Overview

**GFK-Trainer** is a desktop application for learning **Gewaltfreie Kommunikation (GFK – Nonviolent Communication)** based on "Konflikte lösen durch Gewaltfreie Kommunikation: Ein Gespräch mit Gabriele Seils" (Rosenberg/Seils).

**Key Principles:**
- Runs **offline** as an Electron app on Windows, macOS, Linux
- Optional integration with **local LLM** (e.g., LM Studio) via OpenAI-compatible API
- All data stays local; no cloud dependency, no telemetry
- Users **learn by practicing**; LLM provides feedback, not solutions

---

## Your Role as Development Assistant

You work on:

1. **Architecture & Code Structure**
   - Build and maintain Electron foundation (Main/Preload/Renderer)
   - Keep Renderer modular (TypeScript + DOM, lightweight – no heavy frameworks unless discussed)
   - Maintain `src/gfkContent.ts` as the single source of truth for all content

2. **Productivity & Robustness**
   - Suggest types, interfaces, utility functions
   - Implement robust JSON parsing for LLM responses
   - Add helper functions and tests without diluting pedagogical logic

3. **Respect Pedagogical Guardrails**
   - LLM provides **feedback only**, never rewrites user responses
   - **Never** implement "Accept suggestion" or auto-rewrite functionality
   - Goal: Users improve their own phrasing through feedback

## Technical Foundation

### Stack
- **Electron** (Main + Preload + Renderer)
- **Renderer:** TypeScript + DOM (or lightweight framework if approved)
- **No heavy servers**, no login, all local

### Target Directory Structure
```
src/
  main/              # Electron Main process
  preload/           # Preload scripts (secure IPC bridge)
  renderer/          # UI logic (TypeScript + DOM)
  gfkContent.ts      # ✓ Single source of truth: all chapters & exercises
  llm/
    client.ts        # LLM HTTP client
    schema.ts        # Type definitions & response parser
  state/
    state.ts         # Persistence: load/save/import/export progress
```

### Content as Code
- **`src/gfkContent.ts`** exports all chapters/exercises as a structured object
  - Exports: `export const GFK_CHAPTERS: Chapter[]`
  - No text duplication in UI code
  - UI **imports and renders** content, does not hardcode it

## LLM Feedback Schema (Critical)

LLM feedback is **per field** (textarea, matrix row, translate pair, etc.).

### LLM Response Format (JSON)

```jsonc
{
  "exerciseId": "c1e2",           // Unique identifier of the exercise
  "fieldId": "main",              // ID of the field within the exercise
  "present": true,                // Whether element is identifiable
  "score": 2,                     // 0–3 scale (see below)
  "confidence": 0.8,              // LLM confidence in evaluation
  "issues": [
    "Beobachtung ist zu allgemein.",
    "Gefühl ist mit Bewertung vermischt."
  ],
  "suggestions": [
    "Füge eine konkrete Situation/Zeit hinzu.",
    "Formuliere das Gefühl als Wort (z. B. traurig, wütend)."
  ],
  "exampleRewrite": "Als du vorhin das Gespräch beendet hast, wurde ich traurig, weil mir Austausch wichtig ist.",
  "explainers": [
    "Stark: du nennst klar, was dir wichtig ist.",
    "Ausbaufähig: der Beobachtungsteil ist noch unscharf."
  ],
  "meta": {
    "fieldType": "textarea",
    "pairIndex": 0
  }
}
```

### Score Scale (0–3)
- **0:** No usable GFK element
- **1:** Mixed form, much judgment/strategy
- **2:** Mostly appropriate, GFK element clearly identifiable
- **3:** Very clear and concise, only fine-tuning needed

### Guidelines for `exampleRewrite`
- Max 1–2 sentences
- Orientation only, **not ghostwriting**
- Never replace user's own work

## Development Workflow

### Before Writing Code
1. **Check the structure:** Does your suggestion fit the target directory layout?
2. **Respect content separation:** Is `src/gfkContent.ts` the source for all text?
3. **Review existing exports:** Get signatures of exported objects/functions before modifying existing files

### When Modifying Existing Files
- First read the file to understand exports and dependencies
- Preserve export signatures (`export const GFK_CHAPTERS`, etc.)
- Use context-based find-and-replace to maintain integrity

### Code Style & Patterns
- **TypeScript:** Use strict mode; define interfaces for all major types
- **No hardcoded strings** in UI code (import from `gfkContent.ts`)
- **Error handling:** Graceful fallbacks, especially for JSON parsing from LLM
- **Comments:** Brief explanations for non-obvious logic

---

## What NOT to Do

❌ **Silently add telemetry or analytics**  
❌ **Suggest cloud backends** when local storage suffices  
❌ **Change content in `src/gfkContent.ts`** without explicit reason (bugfix, typo, clear pedagogical improvement)  
❌ **Copy-paste long generated text** into exercises (keep content structured and concise)  
❌ **Implement "Accept suggestion" button** or auto-rewrite functionality  
❌ **Duplicate content** between `src/gfkContent.ts` and UI code

## Development Phases (Reference)

### Phase 1: Electron Scaffold
- Create `electron/main.ts`, `electron/preload.ts`, `index.html`
- Basic window rendering

### Phase 2: Renderer & Content Import
- Set up `src/renderer/main.ts`, `src/renderer/ui.ts`
- Import and display `src/gfkContent.ts`
- Chapter navigation, exercise cards

### Phase 3: State Persistence
- Implement `src/state/state.ts`
- Load/save/import/export progress
- Storage: `localStorage` or `IndexedDB`

### Phase 4: LLM Integration
- Build `src/llm/client.ts` (OpenAI-compatible endpoint)
- Implement `src/llm/schema.ts` (types, parser)
- Add "Deep-Check" button per field
- Robust JSON parsing with fallback

### Phase 5: UX Polish & Tests
- Error messages for LLM failures
- Optional unit tests (LLM parser, state import/export)
- Consistent styling, dark mode support

### Phase 6: Packaging (Later)
- Use `electron-builder` for installers
- Windows, macOS, Linux targets

## Questions to Ask Yourself

Before implementing a feature:
1. Where does this data live? (`src/gfkContent.ts`? User state? LLM cache?)
2. Does this encourage the user to **practice and learn**, or bypass learning?
3. Is this local-only, or does it assume internet?
4. Can I add this without breaking existing exports?
